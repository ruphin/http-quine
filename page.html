HTTP quine

A web page that serves itself

This web page is also a binary program. It runs a tiny HTTP server on 127.0.0.1:8080 that serves itself. Thanks to Cosmopolitan Libc it is a Windows program, a Linux and macOS program, and a shell script, all at once.

This is an old idea of mine, but I never had the time and patience to learn the necessary C. Now I can just ask Claude to do the C stuff for me...

Download

Download quine.exe or use Save page as, it is exactly the same.

Run it

Run the binary like you normally would, which should start a web server at http://127.0.0.1:8080/ that you can visit in your browser. It should serve the same page you are looking at right now. Plaform specific instructions on how to run the binary are listed below.

NOTE: Running random programs you download off the internet is usually not a good idea. I understand that you may not want to do this, in which case you'll just have to trust me (bro) that it works. ¯\_(ツ)_/¯

Windows:

double-click quine.exe, or run it from a terminal. It needs the .exe extension to work

Linux and BSD:

chmod +x quine.exe
./quine.exe

macOS:

Requires Xcode Command Line Tools

xattr -d com.apple.quarantine quine.exe
chmod +x quine.exe
./quine.exe

How it works

The heavy lifting is done by Cosmopolitan Libc, which makes it work on most machines.

  • Windows sees MZ at the start of the file, which makes it a valid executable. The first bytes are MZqFpD=', which is a valid DOS header and also the start of a shell string.
  • Linux and macOS refuse to execute the file directly, so the shell runs it as a script. The script locates an embedded loader and maps the real ELF program into memory. The file on disk is never modified.
  • Most of the binary stuff is wrapped in a big HTML comment, with some HTML content attached at the end, which is the page you are looking at right now.
  • The server itself is about 25 lines of C: accept request, read and ignore the content, write HTTP/1.0 200 OK and a content type, write the file, close connection.

Notes

  • Apple Silicon: macOS requires signed native code, so the loader is compiled on first run. You need Xcode Command Line Tools for this (xcode-select --install).
  • Shells: the Unix bootstrap needs dash, bash, or zsh 5.9 or newer. Older zsh fails with "exec format error".
  • Linux/Wine: Linux systems that route MZ files to Wine will try to run it under Wine. Running it as sh quine.exe avoids that.
  • WSL: with Windows interop enabled, ./quine.exe is handed to Windows. Run sh quine.exe instead.
  • Port: fixed at 8080 on loopback only. If the port is taken, the server exits silently.
  • Security: a file with a shell script in its DOS header looks pretty suspicious, and some browsers and antivirus tools will flag it.
  • Not a real HTTP server: it cuts every possible corner to just serve this content.
